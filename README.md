# Decode-generated checkpoint reuse: validation evidence

Related RFC: https://github.com/vllm-project/vllm-ascend/issues/20549

## Implementation

A follow-up request can reuse tokens generated by an earlier decode request, but hybrid attention also needs the corresponding recurrent state and target/MTP alignment. This PR adds opt-in checkpoint reuse to Ascend Store so these states can be saved and restored together.

The implementation consumes vLLM's native boundary offers and committed token hashes, carries accepted checkpoints through the existing connector metadata and bulk transfer path, and retires request bookkeeping through the existing worker lifecycle. Layout descriptions are separated from the GLM adapter. The patch also delegates hybrid chunk splitting to upstream vLLM and aligns scheduled-prefix MTP inputs, circular slot mapping, and explicit C8 block-size handling.

## Configuration

Yes. Joint state reuse is opt-in through `enable_state_store_reuse`. The connector requires `state_store_tp_size` (shared logical TP partition), positive `max_state_save_jobs` and `max_state_save_blocks`, and `kv_load_failure_policy="fail"`. Writers enable the existing `save_decode_cache`; peers share `cache_prefix`. Loading roles use native asynchronous admission. A missing or short read fails the request.

Four accompanying adjustments also apply when state reuse is disabled: native Mamba split delegation, scheduled-prefix MTP backup indexing, circular slot mapping, and honoring an explicit C8 `block_size`.

Validated configuration: GLM-5.3-Flash W8A8 with INT8 MLA cache, BF16 pooled indexer, the V1 model runner, bulk Mooncake transfer, P TP8 and D TP2 × DP4. A release-note draft is included in this review package.
